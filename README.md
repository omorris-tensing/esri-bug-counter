# Esri Security Bug Counter

Tracks **security-related** bug fixes in Esri ArcGIS Enterprise patches over the last 5 years (2021–2026 YTD). Only bugs whose description is security-labeled (XSS, SQL injection, directory traversal, SSRF, CSRF, unvalidated redirect, log4j, etc.) are counted; non-security defect fixes that happen to be listed on the same patch pages are ignored.

Esri does not provide a single, centralized database of fixed bugs. Each patch page on
https://support.esri.com/en-us/patches-updates lists the `BUG-000xxxxxx` identifiers addressed
by that patch. This project scrapes those pages, counts the bug IDs, and reports the totals
per patch, per product, and per year.

## Scope

- **Security patches only** — pages whose title contains "Security" (ArcGIS Server Security,
  Portal for ArcGIS Security, etc.). A small number of adjacent patches that are explicitly
  labeled by Esri as security-relevant (e.g. Web Adaptor Stability, Workflow Manager patches
  that list "Security vulnerability" in their issues) are included for completeness and tagged
  in the `security_label` column.
- **Products covered**: ArcGIS Server, Portal for ArcGIS, ArcGIS Data Store, ArcGIS Web Adaptor,
  ArcGIS Workflow Manager Server.
- **Time window**: patches released in 2021, 2022, 2023, 2024, 2025, and 2026 (through Aug 18, 2026).

## Files

| File | Purpose |
| --- | --- |
| `build_catalog_from_json.py` | Pulls Esri's authoritative `patches.json` and writes `patches_catalog.csv` (security patches since 2023, de-duplicated by URL) |
| `patches_catalog.csv` | Catalog of security patch URLs with product, year, release date, and source flag |
| `patches_catalog.json` | Raw filtered catalog (includes QFE_ID and source for traceability) |
| `scrape_bugs.py` | Fetches each catalog URL, counts distinct `BUG-000xxxxxx` IDs, classifies each as security or non-security |
| `bug_counts.csv` | Output: one row per patch with total + security-labeled bug counts |
| `bugs_detail.csv` | Output: one row per (patch, bug ID) with its short description + `is_security` flag |
| `report.md` | Generated summary report with year-over-year totals and per-product breakdown |
| `make_charts.py` | Generates three PNG charts (light + dark) from `bug_counts.csv` |
| `charts/` | Chart PNGs (patches and fixes per year, product breakdown, timeline); dark-mode twins in `charts/dark/` |
| `cache/` | On-disk cache of fetched patch HTML so re-runs are fast and polite |

## How to run

```bash
python -m pip install -r requirements.txt

# 1. Build the catalog from Esri's authoritative JSON endpoint
python build_catalog_from_json.py

# 2. Scrape each patch page and count BUG IDs (caches HTML under cache/)
python scrape_bugs.py

# 3. Generate the charts into charts/ (and charts/dark/)
python make_charts.py

# Re-run later using only cached HTML (no network):
python scrape_bugs.py --no-fetch
```

## Authoritative source

Esri publishes a machine-readable list of all patches at
`https://content.esri.com/patch_notification/patches.json`. Each entry has a
`Critical` field that Esri sets to `"security"` for security patches. We use
that field (plus a small hand-curated list of patches that mention security
vulnerabilities in their issue text without being flagged `Critical=security`)
as the authoritative catalog. This avoids relying on web search to discover
patch URLs.

## Methodology notes

1. **Catalog source**: `patches_catalog.csv` is generated by `build_catalog_from_json.py`
   from Esri's `patches.json`. We keep patches where `Critical == "security"` OR the patch
   name contains "Security" OR "Log4j", released on or after 2021-01-01. Esri ships many
   per-version URLs for the same patch name (e.g. Log4j, Notebook Server); we consolidate
   those to one row per (name, product, year), keeping the latest release's URL. A small
   `EXTRA_PATCHES` list appends non-flagged patches that nonetheless list explicit
   security vulnerabilities in their issue text (Web Adaptor Stability, Workflow Manager,
   Data Store Reliability).
2. **Counting only NEW bugs per patch**: Each Esri patch page has a main "Issues addressed"
   list followed by cumulative "To avoid conflicts the <version> version also addresses:"
   re-lists of older fixes for backward-version compatibility. **Only the first list is
   counted** — the cumulative re-lists are deliberately excluded, so each patch is only
   credited for the bugs it newly introduces. This means per-year totals are directly
   additive with no double counting across patches.
3. **"Security-labeled" count**: A bug is counted as security-labeled if its description
   contains any of the keywords in `SECURITY_KEYWORDS` (in `scrape_bugs.py`): `security
   vulnerability`, `XSS`, `cross-site scripting`, `SQL injection`, `directory traversal`,
   `LFI`, `RFI`, `SSRF`, `CSRF`, `unvalidated redirect`, `unvalidated file upload`,
   `HTML injection`, `log4j`, `improper authentication`, `unauthorized access`,
   `information disclosure`, `encrypted user-defined setting`, `privilege escalation`, etc.
4. **Mentions without a BUG-ID**: Esri occasionally lists a security fix as plain prose
   with no `BUG-000xxxxxx` identifier (e.g. Workflow Manager "Security vulnerability
   allowing Workflow Administrators to access encrypted user-defined setting values.").
   These are captured separately as `security_mentions_without_bug_id` and shown in the
   report's "Mentions w/o BUG-ID" column. They are NOT added to the bug counts because they
   have no trackable identifier.
5. **Release dates**: Taken from the `ReleaseDate` field in `patches.json`.
6. **Obsolete/replaced patches**: Some older patches are marked obsolete and replaced by
   a newer cumulative patch. The Esri JSON does not surface a "replaced by" relationship, so
   the `replaced_by` column is currently empty; all catalogued patches are treated as active.
   The per-year "unique bug IDs" row de-duplicates across patches released that year so a
   bug re-listed in a replacement patch is only counted once.

## Data sources

- Esri Support "Patches and Updates" pages, e.g.
  https://support.esri.com/en-us/patches-updates/2026/portal-for-arcgis-security-2026-update-3-patch
- Individual bug detail pages, e.g.
  https://support.esri.com/en-us/bug/unable-to-log-in-to-some-endpoints-in-portal-for-arcgis-bug-000162883
